## 2026-11-14 — 테스트 도구와 모듈 형식 변경 (AD-12)

`T-103`에서 NestJS 최신 버전(12)의 기본 구성이 ESM + Vitest임을 확인했다. AD-12(Jest 하나로 통일)의 근거였던 "NestJS와 Expo 모두 Jest가 기본"이 더 이상 맞지 않는다.

## 2026-11-14 — 훈련 안전 규칙의 구조 변경 (D-04 일부)

`T-201` 초안(`docs/T-201-TRAINING-DRAFT.md`)을 교차 검토하면서, 기존 규칙으로는 회복 주를 지날 때마다 훈련량이 줄어 대회 준비 계획을 만들 수 없음을 확인했다. 개발자가 아래 여섯 가지를 승인했고 PRD §7에 반영했다.

| # | 결정 | PRD |
|---|---|---|
| 1 | 주간 증가 한도의 기준을 직전 주에서 최근 4주의 고점으로 바꾼다. 회복 주 다음 주는 고점까지만 복귀한다 | `TE-S01` |
| 2 | 계획을 만들 수 있는지는 대회 전에 도달할 수 있는 최장 달리기 거리로 판정한다. 도달할 수 없으면 완주 준비 계획을 만들지 않고 기초 훈련 계획만 제시한다. 둘 다 가능하면 사용자가 고른다 | `TE-G06`, `F03-R05`, `F03-R06` |
| 3 | 사용자는 목표 기록 값을 유지할 수 있다. 그 선택은 계획의 훈련량과 강도를 올리지 않는다 | `TE-G06` |
| 4 | 최근 주간 거리가 0이거나 없으면 시간 기반 걷고 달리기 계획으로 시작한다. 첫 주는 "쉬지 않고 달릴 수 있는 시간"을 기준으로 한다 | `TE-S06`, `TE-G05`, `TE-S14` |
| 5 | 한 번의 달리기 거리가 최근 30일 최장 거리의 110%를 넘지 않는 규칙을 추가한다 | `TE-S13` |
| 6 | 대회 당일의 거리는 훈련량 계산에서 뺀다 | `TE-S08` |

확정한 것은 규칙의 구조다. 수치(110%, 30일, 4주)는 초기값이고, 목표별 도달 기준 거리, 시간 기반 주의 구성, 입문 계획, 주 2회·4~5회 구성은 정해지지 않았다. 러닝 훈련 전문가의 검토 전에는 D-04를 확정으로 바꾸지 않는다.

함께 바뀐 문서: `API_SPEC.md` §3.3(계획 종류와 미리보기의 선택지), `DATABASE.md` §3.3(`training_plans.kind`), `UI_UX.md` §6.2(계획 종류 선택).

## 2026-11-16 — Training Engine을 초기값으로 먼저 개발한다 (D-04 일부)

전문가 검토를 기다리는 동안 `T-202` 이후의 작업이 모두 멈춰 있어, 개발자가 아래와 같이 정했다. `D-04`는 여전히 확정이 아니다.

| 항목 | 결정 |
|---|---|
| 검증기(`T-202`) | `T-201`을 기다리지 않고 PRD §7.4의 초기값으로 바로 시작한다 |
| 정해지지 않은 예외 | `TE-S01`의 "주간 거리가 매우 적은 구간"과 `TE-S13`의 "실제 기록이 계획보다 짧았을 때"는 예외를 넣지 않고 규칙을 적힌 그대로 적용한다. 예외는 정해지면 더한다 |
| 생성기(`T-203`)에 필요한 값 | 목표별 도달 기준 거리, 시간 기반 주의 구성, 주 2회·4~5회 구성, 수준 분류 기준, 무리한 목표 기록의 판정은 Codex가 `T-201`에서 초기값을 제안해 PR로 올리고, 개발자가 보고 병합하면 쓴다 |
| 수치의 위치 | 모든 수치는 `packages/training-engine`의 설정 상수 한 곳에 (초기값)으로 둔다. 검토 뒤에 값만 바꿀 수 있어야 한다 |

## 2026-11-16 — 검증기의 입력과 판정 기준 (T-202, D-04 일부)

`T-202`의 초안을 교차 검토하면서 PRD §7.4만으로는 판정할 수 없는 부분을 확인했고, 개발자가 아래와 같이 승인했다. `D-04`는 여전히 확정이 아니며 수치는 모두 초기값이다.

| 항목 | 결정 | PRD |
|---|---|---|
| 주의 계산 | 주는 월요일부터 일요일까지다. 검증기는 날짜로 주를 직접 계산하고 입력의 주차를 믿지 않는다 | §1.5, §7.4 |
| 변경안의 검증 입력 | 일정 변경의 변경안을 검증할 때는 변경 전 계획과 변경 사유를 함께 넘긴다(`ValidateInput.change`). 변경 전후의 훈련과 주간 총량을 함께 비교한다. 놓친 훈련을 다른 훈련의 거리 증가로 보충하지 않는다 | `TE-S09` |

| `tempo`의 주 3회 | 그 주에 배치된, 생략하지 않은 훈련의 수로 센다. 훈련을 생략해 주 3회에 못 미치면 변경기가 `tempo`도 함께 바꿔야 한다 | `TE-S07` |

| 형식이 맞지 않는 훈련 | 걷고 달리기가 아닌데 거리가 없거나, 거리와 시간이 모두 없는 훈련은 `TE-S14` 위반으로 보고한다 | `TE-S14` |

| 항목 | 초기값 | PRD |
|---|---|---|
| 수준 분류 | 세 항목 중 가장 낮은 수준. 달릴 수 있는 시간: 30분 미만 입문, 30~60분 초급, 60분 이상 중급. 최근 주간 거리: 없음·10km 미만 입문, 25km 미만 초급, 25km 이상 중급. 경험: 처음 입문, 6개월 미만 초급, 그 이상 중급 | `TE-G01` |

| 기초 훈련 계획 | 도달 조건 없음, 증가율 +5%, `tempo` 없음. 시간 기반으로 시작하는 계획은 항상 기초 훈련 계획이다 | `TE-G06` |
| 조정 주 | 5km·10km는 대회가 있는 주, 하프마라톤은 그 전 주까지. 대회가 있는 주는 고점의 60%로 `easy`만, 하프마라톤의 전 주는 75% | `TE-G02`, `TE-S08` |
| 대회가 월~수요일 | 그 전 주도 대회가 있는 주처럼 줄인다. 검증기도 그 전 주에 같은 기준(고점보다 25% 이상 적음)을 적용한다 | `TE-S08` |
| 대회가 표준 기간보다 멀다 | 앞은 유지 주간(늘리지 않고 4주째마다 회복 주). 도달에 주가 더 필요하면 늘리는 주를 앞당긴다 | `TE-G07` |

## 2026-11-17 — 무료는 맛보기: 가입 체험분과 이용 한도 변경 (D-08), 이미지 첨부 제외

무료 월 10회로는 일정 변경 대화를 3~4번 하면 끝나 코치의 가치를 판단하기 전에 막힌다는 문제에서 출발했다. 하루 단위 한도, 평생 체험분만 주기, 토큰 차감, Pro 기간 체험을 견주어 보고 개발자가 "가입 체험분 + 적은 월 한도"로 정했다. 무료 요금제의 AI 기능은 맛보기다.

| 항목 | 결정 | PRD |
|---|---|---|
| 무료의 구조 | 가입할 때 한 번 주는 체험분을 먼저 쓰고, 다 쓰면 월 한도에서 차감한다. 체험분은 기한이 없고 다시 채워지지 않는다 | §8.1, §8.2 |
| 한도의 단위 | 월 단위를 유지한다. 하루 단위로 바꾸지 않는다 | §8.2 |
| 이미지·파일 첨부 | MVP에서 제외한다. 채팅은 500자 이하의 글자만 받는다 | §1.4, `F04-R09` |
| 세는 단위 | 사용자에게는 횟수로 보여 준다. 토큰이나 크레딧으로 세지 않는다. 메시지 한 건의 비용은 글자 수 제한, 컨텍스트 구성, 출력 토큰 제한, 도구 호출 반복 제한으로 묶는다 | §6.8 |
| 확인 질문의 답 | 따로 묶지 않고 메시지마다 1회로 센다 | §8.2 |
| 무료 체험 기간 | 두지 않는다(`D-10` 그대로) | §8.4 |

수치(모두 초기값. Claude Code가 제안했고 개발자 확인이 필요하다):

| 항목 | 무료 | Pro |
|---|---|---|
| 가입 체험분 | AI 대화 30회, AI 일정 변경 3회 | 해당 없음 |
| AI 대화 | 체험분을 다 쓴 뒤 월 5회 | 월 300회(전에는 100회) |
| AI 일정 변경 | 체험분을 다 쓴 뒤 월 1회 | 월 30회 |

수치의 근거는 추정이다. 메시지 한 건에 입력 약 9,000토큰, 출력 약 400토큰으로 잡으면 가장 작은 모델 등급(입력 $0.10, 출력 $0.50 / 100만 토큰)에서 약 1.5원, 중간 등급에서 약 12원, 상위 등급에서 약 31원이다. 무료 가입자의 최대 비용은 첫 달 35건으로 50~1,100원, 이후 매월 5건으로 8~160원이다. Pro 300건은 460~9,300원이며, 상위 등급을 쓰게 되면 수입(약 6,700원)을 넘으므로 한도를 낮춰야 한다. `T-407`에서 잰 값으로 확정한다. 시스템 지침과 도구 정의가 아직 없어 토큰 수는 어림값이고, OpenAI의 가격은 공식 가격표가 아닌 자료로 봤다.

함께 넣은 것(개발자가 제안했고 Claude Code가 조건을 붙였다. 개발자 확인이 필요하다):

- 놓친 훈련이 많은 주의 일정 변경은 차감하지 않는다. 채팅의 일정 변경 제안을 만드는 시점에 이번 주 미완료 훈련이 2회 이상이고 이번 주에 이 조건으로 승인한 변경이 없을 때다. 서버가 훈련 상태로 판정하고 주 1회다. MVP의 코치는 먼저 말을 걸지 않으므로 "코치가 먼저 제안"은 홈의 미완료 안내로 들어온 대화를 가리키며, 진입 경로를 따로 기록하지 않고 위 조건만 본다.

문서를 고치면서 Claude Code가 정한 것(개발자 확인 필요):

- 체험분의 사용량은 새 테이블 `usage_trials`에 둔다. `usage_counters`의 월 키를 그대로 두기 위해서다.
- Usage 응답에 `pool`(`trial` / `month`)을 더했다. 한도 안내 카드는 월 한도까지 다 썼을 때만 나온다.
- Pro인 동안에는 체험분이 줄지 않고, 무료로 돌아오면 남은 만큼 쓸 수 있다.
- `change_proposals`에 `quota_exempt`를 더했다.
- 구현 작업: 체험분은 `T-410`(이용량 모듈 담당인 Codex), 차감 없는 일정 변경은 `T-403`(Claude Code).
- PRD §8.2 제목의 [제안]을 §15의 `D-08` 상태(확정)에 맞췄다.

아직 정하지 않은 것:

- 나중에 이미지를 받게 될 때의 차감 방식(Pro 전용 또는 여러 회 차감).

탈퇴 뒤 다시 가입한 계정(개발자 결정): 체험분을 다시 주지 않는다. 같은 사용자인지는 로그인 계정으로 판단한다.

| 항목 | 결정 |
|---|---|
| 같은 사용자의 판단 | 로그인 공급자와 공급자가 준 사용자 식별자를 서버 비밀값으로 해시한 값(`identity_hash`)이 같으면 같은 사용자다. 이메일과 이름은 지금처럼 저장하지 않는다 |
| 탈퇴할 때 남기는 것 | `usage_trials`의 해시와 체험분 사용 횟수뿐이다. 프로필, 계획, 기록, 대화는 지금처럼 바로 지운다(`DI-11`) |
| 다시 가입했을 때 | 같은 행을 이어 쓴다. 탈퇴 전에 쓴 횟수에서 이어진다 |
| 보존 기간 | 탈퇴 뒤 1년(초기값). 지나면 내부 작업이 지운다 |

개발자는 "탈퇴해도 데이터를 바로 지우지 말자"고 했으나, Claude Code가 개인 데이터는 바로 지우고 해시와 횟수만 남기는 것으로 좁혀 제안했다(개발자 확인 필요). 계정 삭제 때 개인 데이터를 지우는 것은 `F01-R06`, `DI-11`의 요구이고 스토어의 계정 삭제 기준과도 닿아 있으며, 탈퇴 뒤 보존 항목은 법률 검토(`D-12`) 대상이라 넓게 남기는 쪽을 먼저 정할 수 없다. 해시와 보존 기간도 `D-12`에서 확인하고 개인정보 처리방침에 적는다(`D-A5`).

문서를 고치면서 Claude Code가 정한 것(개발자 확인 필요):

- 계획 종류에 `maintenance`를 더했다. 기초 훈련 계획(`base_building`)으로 저장하면 목표 문구(`focus`)를 첫 주 훈련으로 판정할 때 20분 단계에서 끝난 계획에 이은 유지 계획이 "30분 쉬지 않고 달리기"로 표시되고, 계획을 다시 계산할 때 유지 계획인지 알 수 없다. DB 체크 제약: `goal_distance`가 `none`이면 `kind`는 `base_building` 또는 `maintenance`, `kind`가 `maintenance`면 `goal_distance`는 `none`이다.

- 미리보기 요청의 필드 이름 `continuation`. 끝난 계획이 없으면 `NOT_FOUND`다.
- 대회 전날 알림과 계획 종료 알림은 설정 항목을 따로 두지 않고 예정된 운동 알림의 수신 여부와 시각을 따른다. 대회 전날은 쉬는 날이라(`TE-G08`) 예정된 운동 알림과 겹치지 않는다. 발송은 예정 운동 알림 작업이 함께 하며 내부 작업 엔드포인트를 늘리지 않는다. 무료에도 제공한다(§8.3).

## 2026-11-18 — 유지 계획의 초기값 (TE-G10, D-04 일부)

`T-207`에서 Claude Code가 제안하고 개발자가 확인했다. 전문가 검토(`D-A9`) 전의 초기값이며, 값은 `packages/training-engine/src/safety-config.ts`의 `PLAN.maintenance`에 있다.

| 항목 | 초기값 | 근거 |
|---|---|---|
| 기간 | 4주 | `TE-G03`, `TE-G10` |
| 시작 주간 거리 | 이번 주 전 4주(월~일)의 주마다 "계획 거리"와 "기록 거리" 중 적은 쪽을 잡아 평균한다. 대회 당일 기록은 뺀다. 계획에 거리 기반 훈련이 없던 주(계획이 끝난 뒤)는 기록 거리만 본다. 대회 전 감량 주와 쉰 주도 평균에 들어가 보수적이다 | `TE-G10` "최근 훈련량, 실제 기록이 적으면 적은 쪽" |
| 거리 기반·시간 기반 | 시작 주간 거리가 6km 미만이거나 끝난 계획이 시간 기반이면 시간 기반 유지 계획이다 | `TE-G05` |
| 대회 뒤 첫 주 | 대회 다음 날부터 14일 안에 시작하면 첫 주 주간 거리를 5km 70%, 10km 60%, 하프 50%로 줄인다. 입문 수준은 첫 주를 쉬는 주(4주에 포함)로 두고 다음 주를 같은 비율로 줄여 시작한다. 줄인 주 다음에는 주간 거리와 한 번의 거리를 매주 10% 이내로만 되돌리고 시작 주간 거리를 넘지 않는다. 검증기의 `TE-S13`이 계획 안의 이전 달리기만 보기 때문이다 | `TE-G10`, `TE-S13` |
| 시간 기반으로 끝난 계획 | 끝난 계획에서 마지막으로 기록을 연결한 훈련의 단계(한 번에 달리는 시간)를 4주 내내 유지한다. 30분 훈련, 주 3회까지. 마친 훈련이 없으면 프로필의 "쉬지 않고 달릴 수 있는 시간"으로 정한 시작 단계다 | `TE-G10`, `TE-S14` |
| 훈련 구성 | 거리 기반은 가볍게 달리기와 길게 달리기(주 1회)만 둔다. 조금 빠르게 달리기와 회복 주를 두지 않는다. 고점을 넘지 않아 회복 주가 필요 없다(`TE-S02`) | `TE-G10` |

구현하면서 Claude Code가 정한 것(개발자 확인 필요):

- 검증기의 첫 주 상한(`TE-S14`)은 유지 계획에 한해 "최근에 마친 단계"까지 넓힌다. 프로필에 남은 "쉬지 않고 달릴 수 있는 시간"이 10분 미만인 사용자가 20분 단계까지 마쳤을 때 유지 계획이 1분 단계로 돌아가지 않게 하기 위해서다. Engine 프로필에 `recentRunIntervalMin`을 더했고, 생성기가 끝난 계획의 기록으로만 채운다.
- 유지 계획은 저장된 프로필의 최근 주간 거리 대신 위의 시작 주간 거리로 검증한다(`TE-S01`, `TE-S06`). 생성기가 검증에 쓴 프로필을 결과(`GenerateResult.profile`)로 돌려주고, API는 그 값으로 다시 검증한다(`TE-S12`).
- 대회 뒤 쉬는 주를 둔 입문 수준 사용자는 둘째 주도 줄여서 시작한다(위 표). 쉬는 주 다음에 바로 시작 주간 거리로 돌아가지 않게 했다.
- 시간 기반 유지 계획은 대회 뒤라도 쉬는 주(입문 수준) 말고는 줄이지 않는다. 30분 걷고 달리기라 이미 가볍다.
- 끝난 계획 뒤 [새 목표 설정]은 저장된 프로필을 그대로 쓰고 목표 질문(목표 거리, 목표 기록, 대회 날짜)만 묻는다. 계획 기간 동안 늘어난 최근 주간 거리는 반영하지 않는다. 기록으로 최근 주간 거리를 구하는 방법은 `T-403`에서 정한다.
