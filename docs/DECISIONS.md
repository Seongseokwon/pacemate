## 2026-11-14 — 데이터베이스 설계 v1.0 승인

개발자가 `docs/DATABASE.md`와 그 §8(PRD §9 대비 변경 사항)을 승인했다.

- 목표(Goal)를 `training_plans`에 합친다.
- 온보딩 도중의 답변은 기기에만 저장한다.
- 제안의 만료 상태, 훈련의 완료 상태는 저장하지 않고 조회 시 판정한다.
- `planned_sessions.type`에 대회 당일 표시용 `race`를 둔다.
- 이메일·이름을 저장하지 않는다.
- `push_tokens`, `subscription_events` 테이블을 둔다.
- 모든 테이블에 행 수준 보안을 켜고 정책을 만들지 않는다.

## 2026-11-14 — API 명세 v1.0 승인

개발자가 `docs/API_SPEC.md`와 그 §8을 승인했다.

- 운동 기록의 컨디션·운동 강도는 선택 입력이다. 필수는 날짜·거리·시간이다.
- 활성 계획이 있으면 프로필을 직접 수정할 수 없고, 목표·프로필 변경 제안을 거친다.
- 채팅 재전송은 같은 `clientMessageId`로 다시 보내는 방식이다.
- 기록 중복·페이스 확인은 서버 오류 응답 후 앱이 확인 필드를 붙여 다시 보내는 방식이다.
- 홈 화면 전용 엔드포인트(`GET /v1/home`)를 둔다.

## 2026-11-14 — 자체 디자인 시스템 (UX-00)

Astryx 디자인 시스템(https://astryx.atmeta.com/)의 적용을 검토했다. 웹 전용이라 React Native + Expo(`D-01`)에서 컴포넌트를 쓸 수 없고, 토큰 값만 뽑아 쓰는 방식은 가능했으나 이점이 작았다.

개발자가 **자체 디자인 시스템**으로 결정했다. 토큰과 컴포넌트를 `docs/UI_UX.md`가 정의하고 `apps/mobile/src/ui/`에 직접 구현한다. Astryx의 토큰·테마·패키지를 쓰지 않는다.

`UX-01`~`UX-06`(강조색, 글꼴, 다크 모드, 아이콘, 캘린더, 하단 시트)은 승인 대기다.

## 2026-11-14 — 테스트 도구와 모듈 형식 변경 (AD-12)

`T-103`에서 NestJS 최신 버전(12)의 기본 구성이 ESM + Vitest임을 확인했다. AD-12(Jest 하나로 통일)의 근거였던 "NestJS와 Expo 모두 Jest가 기본"이 더 이상 맞지 않는다.

개발자가 **NestJS 12의 기본 구성을 따르기로** 결정했다.

- `services/api`, `packages/shared`, `packages/training-engine`: ESM, Vitest
- `apps/mobile`: Expo 기본인 Jest
- 불변식 테스트의 fast-check는 그대로다.

함께 정한 것: 패키지는 `dist`로 빌드해 쓰고(`pnpm build`), 린트는 저장소 공통 ESLint를 유지한다(NestJS 기본인 oxlint를 쓰지 않는다).

## 2026-11-14 — 훈련 안전 규칙의 구조 변경 (D-04 일부)

`T-201` 초안(`docs/T-201-TRAINING-DRAFT.md`)을 교차 검토하면서, 기존 규칙으로는 회복 주를 지날 때마다 훈련량이 줄어 대회 준비 계획을 만들 수 없음을 확인했다. 개발자가 아래 여섯 가지를 승인했고 PRD §7에 반영했다.

| # | 결정 | PRD |
|---|---|---|
| 1 | 주간 증가 한도의 기준을 직전 주에서 최근 4주의 고점으로 바꾼다. 회복 주 다음 주는 고점까지만 복귀한다 | `TE-S01` |
| 2 | 계획을 만들 수 있는지는 대회 전에 도달할 수 있는 최장 달리기 거리로 판정한다. 도달할 수 없으면 완주 준비 계획을 만들지 않고 기초 훈련 계획만 제시한다. 둘 다 가능하면 사용자가 고른다 | `TE-G06`, `F03-R05`, `F03-R06` |
| 3 | 사용자는 목표 기록 값을 유지할 수 있다. 그 선택은 계획의 훈련량과 강도를 올리지 않는다 | `TE-G06` |
| 4 | 최근 주간 거리가 0이거나 없으면 시간 기반 걷고 달리기 계획으로 시작한다. 첫 주는 "쉬지 않고 달릴 수 있는 시간"을 기준으로 한다 | `TE-S06`, `TE-G05`, `TE-S14` |
| 5 | 한 번의 달리기 거리가 최근 30일 최장 거리의 110%를 넘지 않는 규칙을 추가한다 | `TE-S13` |
| 6 | 대회 당일의 거리는 훈련량 계산에서 뺀다 | `TE-S08` |

확정한 것은 규칙의 구조다. 수치(110%, 30일, 4주)는 초기값이고, 목표별 도달 기준 거리, 시간 기반 주의 구성, 입문 계획, 주 2회·4~5회 구성은 정해지지 않았다. 러닝 훈련 전문가의 검토 전에는 D-04를 확정으로 바꾸지 않는다.

함께 바뀐 문서: `API_SPEC.md` §3.3(계획 종류와 미리보기의 선택지), `DATABASE.md` §3.3(`training_plans.kind`), `UI_UX.md` §6.2(계획 종류 선택).
