# PaceMate AI(가칭) UI/UX 설계 v1.0

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 (2026-11-14 승인) |
| 작성일 | 2026-11-14 |
| 기준 문서 | `PROJECT_CONTEXT.md` §7, `docs/PRD.md` §5, `docs/API_SPEC.md` |
| 디자인 기준 | 자체 디자인 시스템. 이 문서가 정의한다 |
| 범위 | 디자인 토큰, 컴포넌트, 화면 설계, 문구 기준. 구현 코드는 포함하지 않는다. |

## 0. 문서 사용 규칙

1. 화면의 기능 요구사항은 `PRD.md` §5가 기준이다. 이 문서는 그 화면을 **어떤 모양과 구성으로 만드는지**를 정한다.
2. 색, 간격, 글자 크기, 모서리 값은 §3의 토큰만 쓴다. 화면 코드에 색상 값이나 숫자를 직접 쓰지 않는다.
3. 화면은 §4의 컴포넌트로 조립한다. 목록에 없는 컴포넌트가 필요하면 먼저 제안한다.
4. 이 문서에서 정해야 하는 선택은 §12에 `UX-nn`으로 모았다. 2026-11-14에 모두 승인되었다.

## 1. 디자인 시스템 방침

### 1.1 자체 디자인 시스템

이 앱은 외부 디자인 시스템이나 UI 컴포넌트 라이브러리를 쓰지 않고 **자체 디자인 시스템**을 둔다. 토큰(§3)과 컴포넌트(§4)를 이 문서가 정의하고, `apps/mobile/src/ui/`에 직접 구현한다.

| 방침 | 내용 |
|---|---|
| 토큰의 기준 | 이 문서의 §3이다. 구현은 `apps/mobile/src/ui/tokens.ts` 파일 하나이며, 값을 바꿀 때는 이 문서와 그 파일을 함께 고친다 |
| 컴포넌트 | MVP 화면에 필요한 것만 만든다(§4). React Native의 기본 스타일 기능과 토큰만 쓴다 |
| 의존성 | 디자인 시스템을 위한 패키지를 추가하지 않는다 |
| 범위 | 이 앱 하나다. 다른 제품과 공유하거나 패키지로 배포하지 않는다 |
| 키우는 방식 | 화면에서 같은 모양이 두 번 필요해지면 컴포넌트로 올린다. 쓸 곳이 없는 컴포넌트를 미리 만들지 않는다 |

### 1.2 이렇게 정한 이유

Astryx 디자인 시스템(https://astryx.atmeta.com/)의 적용을 검토했다(2026-11-14).

- Astryx는 웹 전용이다. `react-dom`과 StyleX, 최신 브라우저 CSS 기능이 필요해서 React Native + Expo(`D-01`)에서는 컴포넌트가 실행되지 않는다.
- 토큰 값만 뽑아 쓰는 방식은 가능했다. 하지만 컴포넌트는 어차피 직접 만들어야 하고, 데스크톱 밀도에 맞춰진 기본값(본문 14px, 버튼 28~36px)도 모바일에 맞게 다시 정해야 했다. 베타 단계의 외부 패키지에 토큰을 묶어 둘 이유가 남지 않는다.
- 그래서 개발자가 자체 디자인 시스템으로 결정했다. 값과 이름은 이 프로젝트가 정하고, Astryx의 토큰·테마·패키지를 쓰지 않는다.

### 1.3 설계 기준

| 기준 | 내용 |
|---|---|
| 무채색 바탕에 의미 있는 색만 | 바탕, 글자, 주 버튼은 무채색이다. 색은 훈련 종류(§8.1)와 상태(§8.2)에만 쓴다. 화면에 색이 보이면 뜻이 있다 |
| 모바일 밀도 | 본문 17, 터치 영역 44 이상, 화면 좌우 여백 16 |
| 4 단위 간격 | 모든 여백과 간격은 4의 배수다 |
| 테두리로 구분 | 카드와 입력창은 그림자 대신 1px 테두리로 구분한다 |
| 대비 | 글자는 4.5:1 이상, 아이콘과 색 점은 3:1 이상이다. §3.2와 §8.1의 조합은 라이트·다크 모두 계산해 확인했다 |

## 2. 디자인 원칙

`PROJECT_CONTEXT.md` §7.3의 UX 원칙 6개가 우선하고, 그 위에 아래 원칙을 둔다.

| # | 원칙 | 실천 |
|---|---|---|
| 1 | 컴포넌트 우선 | 화면 코드에서 기본 요소(`View`, `Text`)에 직접 스타일을 입히지 않는다. §4의 컴포넌트를 조립한다 |
| 2 | 의미 토큰만 사용 | `text.primary`, `background.surface`처럼 역할로 이름 붙은 토큰만 쓴다. 색상 값과 숫자를 직접 쓰지 않는다 |
| 3 | 값이 한 곳에만 있는 코드 | 강조색이나 글자 크기를 바꿔도 화면 코드는 그대로다. 토큰 파일만 고친다 |
| 4 | 화면 틀 먼저 | 화면의 틀(머리글, 본문, 하단 고정 영역)을 먼저 잡고 내용을 채운다 |
| 5 | 목록은 행으로 | 훈련 목록, 기록 목록처럼 같은 종류가 반복되는 것은 구분선이 있는 행으로 보여 준다. 카드는 오늘의 훈련, 변경 제안, 요약처럼 독립된 덩어리에만 쓴다 |
| 6 | 상태는 점과 칩으로 | 완료·예정·미완료·생략은 상태 점과 글자가 있는 칩으로 표시한다. 숫자 배지는 개수에만 쓴다 |
| 7 | 색만으로 구분하지 않는다 | 상태와 훈련 종류는 색에 더해 아이콘이나 글자를 함께 쓴다 |
| 8 | AI가 할 일을 먼저 보여 준다 | 데이터가 바뀌는 일은 항상 변경 전후를 카드로 보여 주고 버튼으로 확정한다(`F05-R03`, `F05-R04`) |

## 3. 디자인 토큰

### 3.1 토큰 정의

- 토큰은 `apps/mobile/src/ui/tokens.ts` 한 파일에 라이트와 다크 값을 함께 정의한다. 컴포넌트는 `useTheme()`으로 현재 모드의 값을 받는다.
- 토큰 이름은 역할을 말한다(`color.text.primary`). 색 이름(회색, 파랑)으로 부르지 않는다.
- 아래 표의 값이 기준이다. 값을 바꾸면 이 문서와 토큰 파일을 함께 고치고, 색을 바꿀 때는 대비(§1.3)를 다시 확인한다.

### 3.2 색상

| 토큰 | 용도 | 라이트 | 다크 |
|---|---|---|---|
| `background.body` | 화면 바탕 | `#F5F5F5` | `#111111` |
| `background.surface` | 카드, 머리글, 입력창, 시트 | `#FFFFFF` | `#1C1C1C` |
| `background.muted` | 옅은 채움, 사용자 말풍선 | `#EFEFEF` | `#262626` |
| `text.primary` | 본문, 제목, 주 아이콘 | `#111111` | `#F5F5F5` |
| `text.secondary` | 보조 설명, 날짜 | `#555555` | `#A8A8A8` |
| `text.disabled` | 비활성 | `#9A9A9A` | `#5E5E5E` |
| `icon.secondary` | 보조 아이콘 | `#6B6B6B` | `#A8A8A8` |
| `accent` | 주 버튼, 선택 표시, 개수 배지 | `#111111` | `#F5F5F5` |
| `onAccent` | `accent` 위의 글자 | `#FFFFFF` | `#111111` |
| `accentMuted` | 선택된 항목의 옅은 채움 | `#E3E3E3` | `#3A3A3A` |
| `border` | 카드 테두리, 구분선 | `#0000001A` | `#FFFFFF1F` |
| `borderEmphasized` | 입력창 테두리 | `#CFCFCF` | `#4A4A4A` |
| `overlay` | 시트·대화 상자 뒤의 어둠 | `#00000080` | `#000000B3` |
| `skeleton` | 로딩 자리 표시 | `#EBEBEB` | `#2E2E2E` |

상태 색은 네 가지이고 각각 두 가지로 쓴다.

| 쓰임 | 토큰 | 예 |
|---|---|---|
| 바탕이나 카드 위의 상태 글자·아이콘 | `text.success` 등 | "완료" 글자, 체크 아이콘 |
| 옅은 채움과 그 위의 글자 | `successMuted` + `text.success` | 안내 띠(배너), 상태 칩 |

| 상태 | `text.*` 라이트 / 다크 | `*Muted` 라이트 / 다크 |
|---|---|---|
| success | `#1B7A33` / `#7FD492` | `#DDF2E1` / `#7FD49233` |
| warning | `#8A6100` / `#F0C75A` | `#FBEBC2` / `#F0C75A33` |
| error | `#C0262C` / `#FF9C96` | `#FBDAD8` / `#FF9C9633` |
| info | `#0B5FC4` / `#8DBEFF` | `#DCEAFB` / `#8DBEFF33` |

강조색은 무채색이다. 브랜드 색을 정하면 `accent`, `onAccent`, `accentMuted` 세 값만 바꾼다(`UX-01`). 이때 `onAccent`와의 대비가 4.5:1 이상인지, 훈련 종류 색(§8.1)과 헷갈리지 않는지 확인한다.

### 3.3 간격

4px 단위다. 여백과 간격에는 이 값만 쓴다.

| 토큰 | 값 | 주 용도 |
|---|---|---|
| `spacing.1` | 4 | 아이콘과 글자 사이 |
| `spacing.2` | 8 | 칩 안쪽, 가까운 요소 사이 |
| `spacing.3` | 12 | 행 안의 요소 사이, 목록 항목 사이 |
| `spacing.4` | 16 | **화면 좌우 여백, 카드 안쪽 여백** |
| `spacing.6` | 24 | 화면의 구역 사이 |
| `spacing.8` | 32 | 큰 구역 사이, 빈 상태의 위아래 |

그 밖에 `spacing.0`(0), `0.5`(2), `1.5`(6), `5`(20), `7`(28), `9`~`12`(36~48)가 있다.

### 3.4 모서리

| 토큰 | 값 | 용도 |
|---|---|---|
| `radius.inner` | 6 | 칩, 카드 안의 작은 요소 |
| `radius.element` | 10 | 버튼, 입력창 |
| `radius.container` | 12 | 카드 |
| `radius.page` | 28 | 하단 시트의 위쪽 모서리 |
| `radius.chat` | 28 | 말풍선, 채팅 입력창 |
| `radius.full` | 9999 | 원형 버튼, 상태 점 |

### 3.5 글자

| 역할 | 크기 / 줄 높이 | 굵기 | 용도 |
|---|---|---|---|
| `display` | 35 / 44 | 600 | D-day 숫자, 큰 통계 숫자 |
| `title1` | 24 / 32 | 600 | 화면 제목 |
| `title2` | 20 / 28 | 600 | 구역 제목, 카드 제목 |
| `title3` | 17 / 24 | 600 | 행 제목, 강조 본문 |
| `body` | 17 / 24 | 400 | 본문, 채팅 |
| `label` | 17 / 24 | 500 | 버튼 글자 |
| `supporting` | 14 / 20 | 400 | 보조 설명 |
| `chip` | 14 / 20 | 500 | 칩, 탭 |
| `caption` | 12 / 18 | 400 | 시각, 부가 정보. 가장 작은 크기 |

- 크기는 12, 14, 17, 20, 24, 35 여섯 가지뿐이다. 다른 크기를 쓰지 않는다.
- 글꼴은 시스템 글꼴이다(`UX-02`).
- 숫자가 나란히 놓이는 곳(페이스, 거리, 시간)은 고정 폭 숫자를 쓴다.
- 기기의 글자 크기 설정을 따른다. 배율 상한은 1.3배(초기값)로 두어 화면이 깨지지 않게 한다.

### 3.6 크기와 터치 영역

| 대상 | 값 |
|---|---|
| 주 버튼 높이 | 52 |
| 일반 버튼·입력창 높이 | 44 (입력창은 48) |
| 아이콘 버튼 | 보이는 크기 36, 터치 영역 44×44 |
| 목록 행 최소 높이 | 56 |
| 아이콘 | 20(행 안), 24(머리글·탭) |
| 최소 터치 영역 | 44×44 |

### 3.7 그림자와 테두리

카드와 입력창은 그림자 없이 1px 테두리(`border`)로 구분한다. 그림자는 바탕 위에 떠 있는 것에만 쓴다.

| 단계 | 쓰는 곳 |
|---|---|
| 낮음 | 화면 하단 고정 버튼 영역 |
| 중간 | 토스트 |
| 높음 | 하단 시트, 대화 상자 |

값은 구현 시 iOS와 Android의 그림자 방식에 맞춰 토큰 파일에 직접 정의한다.

### 3.8 모션

| 토큰 | 값 | 용도 |
|---|---|---|
| `duration.fast` | 120ms | 눌림, 선택 전환 |
| `duration.medium` | 300ms | 시트·대화 상자의 등장과 퇴장, 카드 상태 전환 |
| `duration.slow` | 700ms | 진행률 채워짐 |
| `ease.standard` | 빠르게 시작해 부드럽게 멈춤 | 기본, 등장 |
| `ease.exit` | 천천히 시작해 빠르게 사라짐 | 퇴장 |

기기의 "동작 줄이기" 설정이 켜져 있으면 이동 애니메이션을 없애고 투명도 전환만 200ms 이하로 쓴다.

## 4. 컴포넌트

`apps/mobile/src/ui/`에 둔다. 앱이 하나이므로 별도 패키지로 나누지 않는다. React Native의 기본 스타일 기능과 §3의 토큰만으로 만들고, 스타일 라이브러리를 추가하지 않는다.

### 4.1 공통 컴포넌트

| 분류 | 컴포넌트 | 용도 |
|---|---|---|
| 틀 | `Screen` | 화면의 틀. 안전 영역, 머리글, 스크롤 본문, 하단 고정 영역, 로딩·오류 상태 |
| 틀 | `Stack` | 가로·세로로 나열하고 간격을 준다 |
| 틀 | `Section` | 제목이 있는 구역 |
| 틀 | `Divider` | 구분선 |
| 내용 | `Text`, `Heading` | 글자. §3.5의 역할을 받는다 |
| 내용 | `Icon` | 아이콘. 의미 이름을 받는다(§8.3) |
| 내용 | `EmptyState` | 빈 상태. 아이콘, 한 줄 설명, 버튼 하나 |
| 동작 | `Button` | 종류: 주 / 보조 / 글자만 / 위험. 크기: 일반 / 큼. 로딩 상태 |
| 동작 | `IconButton` | 아이콘만 있는 버튼. 접근성 이름 필수 |
| 동작 | `SegmentedControl` | 둘 중 하나 고르기(주간 / 월간) |
| 담기 | `Card` | 독립된 덩어리 |
| 담기 | `ClickableCard` | 눌러서 이동하는 카드 |
| 담기 | `SelectableCard` | 고르는 카드(온보딩 선택지, 요금제) |
| 입력 | `Field` | 이름표, 도움말, 오류 문구를 입력 요소에 붙인다 |
| 입력 | `TextInput`, `TextArea`, `NumberInput` | 글자·메모·숫자 입력 |
| 입력 | `Switch` | 켜고 끄기(알림 설정) |
| 입력 | `Selector` | 여러 값 중 하나. 하단 시트로 고른다 |
| 입력 | `DateInput` | 날짜. 기기의 날짜 선택기를 쓴다 |
| 입력 | `ScaleInput` | 1~5, 1~10 중 하나 고르기(컨디션, 운동 강도) |
| 알림 | `Banner` | 화면이나 카드 안의 안내 띠. 상태: info / success / warning / error |
| 알림 | `Toast` | 잠깐 떴다 사라지는 결과 알림 |
| 알림 | `StatusDot` | 상태 점 |
| 알림 | `Chip` | 글자가 있는 칩(상태, 훈련 종류) |
| 알림 | `Badge` | 개수 |
| 알림 | `ProgressBar` | 진행률 |
| 알림 | `Skeleton`, `Spinner` | 로딩 |
| 겹침 | `BottomSheet` | 아래에서 올라오는 시트(훈련 상세, 선택) |
| 겹침 | `Dialog` | 확인이 필요한 일(삭제, 로그아웃) |
| 목록 | `List`, `ListItem` | 구분선이 있는 행 목록. 왼쪽 요소, 제목, 설명, 오른쪽 요소 |
| 이동 | `TabBar` | 하단 탭. 화면 이동 라이브러리의 탭을 토큰으로 꾸민다 |
| 이동 | `Stepper` | 온보딩 진행 표시 |

### 4.2 채팅 컴포넌트

| 컴포넌트 | 용도 |
|---|---|
| `ChatLayout` | 대화 목록과 하단 입력 영역의 틀. 키보드가 올라오면 입력 영역이 함께 올라온다 |
| `ChatMessage` | 말풍선. `sender`: user / assistant |
| `ChatSystemMessage` | 서버가 만든 결과 메시지. 말풍선 없이 가운데에 작은 글자와 아이콘 |
| `ChatComposer` | 입력창과 보내기 버튼. 응답 대기 중에는 비활성 |
| `QuickReplies` | 빠른 질문 추천. 가로로 넘기는 칩 |
| `TypingIndicator` | 응답 대기 표시 |

### 4.3 제품 컴포넌트

| 컴포넌트 | 용도 |
|---|---|
| `SessionRow` | 훈련 한 줄: 종류 색, 종류 이름, 거리, 상태 |
| `TodayCard` | 홈의 오늘 훈련 카드 |
| `WeekStrip` | 한 주의 요일 7칸과 훈련 표시 |
| `MonthGrid` | 월간 달력 |
| `ProposalCard` | 변경 제안 카드(§7.2) |
| `SummaryCard` | 주간 요약, 이번 주 훈련 요약 |
| `LimitCard` | 한도 안내 |
| `WorkoutRow` | 기록 한 줄: 날짜, 거리, 시간, 페이스 |
| `StatTile` | 숫자 하나와 이름표(이번 주 거리 등) |
| `UsageMeter` | 남은 이용량 |

### 4.4 컴포넌트 규칙

1. 색, 간격, 글자 크기를 속성으로 받지 않는다. `variant`, `size`, `status`처럼 뜻이 있는 속성만 받는다.
2. 누를 수 있는 것은 모두 눌림 표시가 있고 터치 영역이 44×44 이상이다.
3. 서버에서 데이터를 받는 컴포넌트는 로딩(자리 표시), 빈 상태, 오류 상태를 가진다.
4. 입력 컴포넌트는 값과 변경 함수를 밖에서 받는다.
5. 접근성 이름과 역할을 컴포넌트 안에서 지정한다(§10).

## 6. 화면별 설계

기능 요구사항과 예외는 PRD §5의 같은 화면 절에 있다.

### 6.1 로그인, 동의

- 로그인: 화면 가운데에 서비스 이름과 한 줄 소개, 하단에 Apple 로그인 버튼과 Google 로그인 버튼. 각 플랫폼의 로그인 버튼 지침(모양, 문구)을 따른다.
- 동의: 필수 항목 3개를 `ListItem`과 체크로 나열한다. 각 항목에 [전문 보기]. 맨 위에 "모두 동의". 세 항목이 모두 체크되어야 하단 주 버튼이 활성화된다.

### 6.2 온보딩

- 한 화면에 질문 하나. 위쪽에 `Stepper`(진행률)와 뒤로 가기, 가운데에 질문(`title1`)과 선택지, 하단에 [다음].
- 선택지는 `SelectableCard`로 세로 나열한다. 선택하면 바로 다음으로 넘어가지 않고 [다음]을 눌러야 넘어간다.
- 숫자 입력(주간 거리, 최근 기록)에는 "잘 모르겠어요"를 글자 버튼으로 둔다.
- 요일 선택은 요일 7개를 한 줄에 원형 버튼으로 놓는다. 가능 횟수보다 적게 고르면 [다음]이 비활성이고 이유를 보조 글자로 알린다.
- 선택 항목(목표 기록, 대회 날짜)에는 [건너뛰기].
- 계획 생성 중에는 `Spinner`와 "계획을 만들고 있어요".
- 계획 미리보기: 요약 `StatTile` 3개(전체 주 수, 주당 횟수, 종료일) → 경고가 있으면 `Banner`(warning) → 첫 주 일정 `SessionRow` 목록 → 하단 [이 계획으로 시작], 글자 버튼 [답변 수정].
- 완주 준비 계획과 기초 훈련 계획을 모두 만들 수 있으면 미리보기 위에 `SelectableCard` 두 개로 고르게 한다. 고른 계획의 요약과 첫 주 일정이 아래에 보인다. 하나만 만들 수 있으면 선택 없이 그 계획을 보여 주고, 완주 준비 계획을 만들 수 없는 이유를 `Banner`(info)로 알린다.

### 6.3 홈

```text
┌─────────────────────────────────┐
│ 안녕하세요                        │
│ 하프마라톤 · D-42                 │  display 숫자
│ ████████░░░░░░░  12 / 36 완료     │  ProgressBar
├─────────────────────────────────┤
│ ┌─ 오늘의 훈련 ────────────────┐  │  TodayCard
│ │ ● 가볍게 달리기               │  │
│ │ 5km · 편하게 대화할 수 있는 속도 │  │
│ │ [기록하기]                    │  │
│ └─────────────────────────────┘  │
│ ┌─────────────────────────────┐  │  매니저 메시지 (ClickableCard)
│ │ 💬 어제 훈련을 놓쳤어요.        │  │
│ │    이번 주 일정을 다시 짤까요?   │  │
│ └─────────────────────────────┘  │
│ 이번 주                          │  Section
│ 월 ● 가볍게 달리기 5km      완료   │  SessionRow
│ 수 ● 조금 빠르게 달리기 6km  예정   │
│ 토 ● 길게 달리기 12km       예정   │
└─────────────────────────────────┘
```

- 오늘 훈련이 없으면 `TodayCard`에 "오늘은 쉬는 날이에요"를 보여 준다.
- 오늘 훈련을 이미 기록했으면 버튼 대신 완료 표시와 기록 요약을 보여 준다.
- 매니저 메시지를 누르면 AI 코치로 이동한다.
- 활성 계획이 없으면 화면 전체가 `EmptyState`와 [새 목표 설정]이다.
- 대회 날짜가 없으면 D-day 대신 "N주차 / 전체 M주"를 보여 준다.

### 6.4 AI 코치

```text
┌─────────────────────────────────┐
│ AI 코치              AI 대화 3/10 │  UsageMeter
├─────────────────────────────────┤
│              이번 주 금~일 여행이야. │  ChatMessage (user)
│              훈련 일정 다시 만들어 줘│
│                                 │
│ 여행 일정에 맞춰 이렇게 바꿔 볼게요. │  ChatMessage (assistant)
│ 길게 달리기는 목요일로 옮기고,      │
│ 금요일 훈련은 쉬어 가요.           │
│ ┌─ 일정 변경 제안 ─────────────┐  │  ProposalCard
│ │ 길게 달리기 12km             │  │
│ │ 토 11/21 → 목 11/19          │  │
│ │ 가볍게 달리기 5km      생략   │  │
│ │ 이번 주 거리 23km → 18km     │  │
│ │ [취소]        [적용하기]      │  │
│ └─────────────────────────────┘  │
├─────────────────────────────────┤
│ (이번 주 훈련 알려 줘) (오늘 피곤해) │  QuickReplies
│ ┌───────────────────────────┐ ➤ │  ChatComposer
│ └───────────────────────────┘   │
└─────────────────────────────────┘
```

- 세부는 §7에 있다.
- 처음 들어오면 대화 대신 인사말과 빠른 질문을 크게 보여 준다.
- 한도에 도달하면 입력창 위에 `LimitCard`가 대화의 마지막에 나타나고, 입력창은 그대로 둔다(다시 보내면 같은 안내가 나온다).

### 6.5 캘린더

```text
┌─────────────────────────────────┐
│ 캘린더               [주간|월간]  │  SegmentedControl
├─────────────────────────────────┤
│ ‹  11월 3주차 (16일~22일)  ›      │
│ 월  화  수  목  금  토  일         │  WeekStrip
│ 16  17  18 [19] 20  21  22       │  오늘은 테두리, 선택일은 채움
│ ●       ●   ●                   │  훈련 종류 색 점
├─────────────────────────────────┤
│ 11월 19일 (목)                    │
│ ● 길게 달리기 12km   변경됨 · 예정  │  SessionRow → 누르면 훈련 상세
└─────────────────────────────────┘
```

- 주간 보기는 좌우로 쓸어 주를 넘긴다. 월간 보기는 `MonthGrid`이고 날짜를 누르면 아래 목록이 바뀐다.
- 훈련이 없는 날을 고르면 "쉬는 날이에요".
- 날짜 칸의 표시: 예정은 종류 색 점, 완료는 체크, 미완료는 빈 테두리 점, 생략은 표시 없음.
- 훈련 상세는 `BottomSheet`다: 종류 칩과 상태 칩 → 거리·권장 강도 → 설명 → 변경된 훈련이면 "원래 일정: 11월 21일 (토)" → 연결된 기록 또는 [기록하기] → 글자 버튼 [AI에게 변경 요청].

### 6.6 운동 기록

- 기록 탭: `StatTile` 2×2(이번 주 거리·횟수, 이번 달 거리·횟수) → 주간 분석 `SummaryCard` → 기록 목록(`WorkoutRow`, 월별 구역 제목) → 오른쪽 위 [+].
- 주간 분석 카드: 완료 횟수 / 계획 횟수, 총 거리, 달성률 `ProgressBar`. Pro는 그 아래에 AI 피드백 문장, 무료는 "Pro에서 AI 피드백을 받아 보세요" 한 줄과 화살표.
- 기록 입력(전체 화면): 날짜 → 거리 → 시간 → 자동 계산된 페이스(읽기 전용) → 컨디션 `ScaleInput`(선택) → 운동 강도 `ScaleInput`(선택) → 메모(선택) → 연결할 훈련 `Selector` → 하단 고정 [저장].
- 거리와 시간은 숫자 키패드로 받는다. 시간은 시·분·초 세 칸이다.
- 훈련 상세에서 들어오면 날짜와 연결할 훈련이 채워져 있다.
- 중복이나 비정상 페이스로 서버가 확인을 요청하면 `Dialog`로 묻는다(`WORKOUT_DUPLICATE`, `PACE_OUT_OF_RANGE`).

### 6.7 마이페이지

- `List`로 구성한다: 프로필·목표 → 구독(현재 요금제, `UsageMeter` 2개, 다음 초기화 날짜) → 알림 설정 → 약관·정책 → 문의 → 로그아웃 → 계정 삭제(위험 색).
- 목표·프로필을 수정하고 저장하면 변경 미리보기 화면이 뜬다. 채팅의 `ProposalCard`와 같은 내용을 전체 화면으로 보여 주고 [적용하기], [취소].
- 계정 삭제는 삭제되는 내용과 구독 해지 안내를 보여 준 뒤 `Dialog`로 한 번 더 확인한다.

### 6.8 페이월

- 위에서부터: 닫기 버튼 → 제목 → Pro 혜택 4줄(아이콘과 한 줄씩) → 요금제 `SelectableCard` 2개(연간이 기본 선택, 월 환산 금액 표시) → 주 버튼 [구독하기] → 글자 버튼 [구독 복원] → 자동 갱신·해지 안내와 약관 링크(`caption`).
- 가격은 스토어가 알려 준 값을 그대로 표시한다. 화면에 금액을 직접 쓰지 않는다.
- 결제 확인이 늦으면 버튼을 `Spinner`와 "확인하고 있어요"로 바꾼다.

### 6.9 공통 상태

| 상태 | 표현 |
|---|---|
| 처음 로딩 | 실제 배치와 같은 모양의 `Skeleton`. 화면 전체 `Spinner`는 계획 생성처럼 기다림이 긴 경우에만 |
| 다시 불러오기 | 아래로 당기기. 기존 내용을 지우지 않는다 |
| 빈 상태 | `EmptyState`: 아이콘, 한 문장, 할 수 있는 일 버튼 하나 |
| 오류 | 화면 전체가 실패하면 `EmptyState`와 [다시 시도]. 일부 동작이 실패하면 `Toast` 또는 그 자리의 `Banner` |
| 네트워크 끊김 | 화면 위에 `Banner`(warning) "인터넷 연결을 확인해 주세요" |
| 업데이트 필요 | 닫을 수 없는 전체 화면과 스토어로 가는 버튼(`APP_UPDATE_REQUIRED`) |

## 7. 채팅과 변경 제안

제품의 핵심 경험이다. 처리 흐름은 PRD §6에 있다.

### 7.1 대화

| 항목 | 설계 |
|---|---|
| 사용자 메시지 | 오른쪽, `background.muted` 말풍선, 모서리 `radius.chat` |
| AI 메시지 | 왼쪽, 말풍선 없이 본문 글자. 카드가 있으면 글자 아래에 붙는다 |
| 시스템 메시지 | 가운데, `caption`, 아이콘과 한 줄(예: "✓ 일정을 변경했어요") |
| AI 글 표시 | 일반 글자로 표시한다. 마크다운을 해석하지 않으므로 시스템 지침에 마크다운을 쓰지 않도록 넣는다 |
| 응답 대기 | `TypingIndicator`. 입력창과 보내기 버튼 비활성(`CHAT_BUSY` 방지) |
| 응답 실패 | 사용자 메시지 아래에 `text.error` 색 "보내지 못했어요"와 [다시 보내기] |
| 날짜 구분 | 날짜가 바뀌는 곳에 날짜 구분선 |
| 이전 대화 | 위로 스크롤하면 이어서 불러온다 |
| 빠른 질문 | 입력창 위의 칩. 누르면 바로 전송한다 |
| 이용량 | 머리글 오른쪽에 "AI 대화 3/10". 누르면 구독 화면 |
| 훈련 지정 진입 | 훈련 상세의 [AI에게 변경 요청]으로 들어오면 입력창 위에 대상 훈련 칩("길게 달리기 · 11/21")을 보여 주고 X로 뗄 수 있다 |

### 7.2 변경 제안 카드

```text
┌─ 🔄 일정 변경 제안 ──────────────┐
│ 길게 달리기 12km                 │  변경되는 훈련
│ 토 11/21  →  목 11/19            │  변경 전 → 변경 후
│ ─────────────────────────────  │
│ 가볍게 달리기 5km         [생략]  │  생략되는 훈련 (Chip)
│ 금 11/20                        │
│ ─────────────────────────────  │
│ 이번 주 거리  23km → 18km        │  영향 요약
│ ⚠ 이번 주 훈련이 1회 줄어요       │  경고 (있을 때만, Banner)
│                                 │
│ [ 취소 ]          [ 적용하기 ]    │
│ AI 일정 변경 1/2회 사용 · 내일 15시까지 │  caption
└─────────────────────────────────┘
```

| 카드 종류 | 제목 | 내용 | 승인 버튼 |
|---|---|---|---|
| 일정 변경 | 일정 변경 제안 | 훈련별 변경 전 → 후, 생략, 영향 요약 | 적용하기 |
| 목표 변경 | 목표 변경 제안 | 목표 변경 전 → 후, 바뀌는 훈련 수, 이후 주간 구성 요약 | 적용하기 |
| 기록 등록 | 기록 확인 | 날짜, 거리, 시간, 페이스, 연결할 훈련 | 기록 저장 |

카드의 상태 (`Proposal.status`와 대응)

| 상태 | 표현 |
|---|---|
| 대기 | 버튼 두 개 활성 |
| 승인 처리 중 | [적용하기]가 `Spinner`로 바뀌고 두 버튼 비활성 |
| 승인됨 | 버튼 자리에 `text.success` 색 "✓ 적용했어요"와 글자 버튼 [캘린더에서 보기] |
| 취소됨 | 버튼 자리에 "취소한 제안이에요". 카드 전체를 흐리게 |
| 대체됨 | "새 제안으로 바뀌었어요". 흐리게 |
| 만료 | "기간이 지난 제안이에요. 다시 요청해 주세요". 흐리게 |
| 승인 실패 | 카드 안에 `Banner`(error)로 서버의 `message`를 보여 준다. 다시 요청해야 하는 실패(`PLAN_CHANGED` 등)면 버튼을 없애고, 일시적 실패면 [다시 시도] |
| 한도 초과 | 카드는 대기 상태로 두고 아래에 `LimitCard` |

설계 규칙:

1. 카드의 내용은 서버가 준 Proposal 객체로만 그린다. AI의 문장을 카드에 넣지 않는다.
2. [적용하기]는 카드의 유일한 주 버튼이다. [취소]는 보조 버튼이다.
3. 승인이 끝나면 햅틱 한 번과 시스템 메시지로 알린다. 화면을 자동으로 옮기지 않는다.
4. 변경 전후는 같은 줄에 화살표로 놓는다. 생략되는 훈련은 취소선 없이 "생략" 칩으로 표시한다(취소선은 읽기 어렵다).
5. 이용량이 차감되는 제안에는 버튼 아래에 "AI 일정 변경 1/2회 사용"을 보여 준다. 차감되지 않는 제안(기록 등록)에는 보여 주지 않는다.

### 7.3 한도 안내 카드

제목 "이번 달 AI 대화를 모두 썼어요", 다음 초기화 날짜, "캘린더와 기록은 계속 쓸 수 있어요", 주 버튼 [Pro 알아보기]. 위협하거나 재촉하는 문구를 쓰지 않는다.

## 8. 훈련 종류, 상태, 아이콘

### 8.1 훈련 종류

색만으로 구분하지 않고 항상 종류 이름을 함께 쓴다. 색은 점, 달력 표시, 칩의 테두리처럼 작은 면적에만 쓴다.

| `type` | 표시 이름 | 토큰 | 라이트 | 다크 | 체감 안내 문구 |
|---|---|---|---|---|---|
| `walk_run` | 걷고 달리기 | `session.walkRun` | `#0E8F8F` | `#3FC4C4` | 걷기와 달리기를 번갈아 해요 |
| `easy` | 가볍게 달리기 | `session.easy` | `#1E6FE0` | `#5B9DFF` | 편하게 대화할 수 있는 속도예요 |
| `tempo` | 조금 빠르게 달리기 | `session.tempo` | `#D9620A` | `#FF9447` | 숨이 조금 차지만 유지할 수 있는 속도예요 |
| `long` | 길게 달리기 | `session.long` | `#6B3FE0` | `#A58BFF` | 편한 속도로 평소보다 오래 달려요 |
| `race` | 대회 | `session.race` | `#D63A9E` | `#FF7CCB` | 대회 날이에요 |

표시 이름과 문구는 `packages/shared`에 둔다(API_SPEC §2.2).

### 8.2 훈련 상태

| `status` | 칩 문구 | 색 | 아이콘 |
|---|---|---|---|
| `planned` | 예정 | `text.secondary` | 없음 |
| `completed` | 완료 | `text.success` | 체크 |
| `missed` | 미완료 | `text.warning` | 빈 원 |
| `skipped` | 생략 | `text.disabled` | 없음 |

미완료에 오류 색(빨강)을 쓰지 않는다. 훈련을 놓친 것은 잘못이 아니다.

### 8.3 아이콘

아이콘은 의미 이름으로 부르고, 실제 아이콘과의 대응은 파일 하나에 둔다. 아이콘 세트를 바꿀 때 그 파일만 고친다. 세트는 `UX-04`에서 정한다.

필요한 의미 이름: `home`, `coach`, `calendar`, `record`, `profile`, `run`, `walk`, `flag`, `check`, `close`, `back`, `next`, `add`, `edit`, `delete`, `send`, `swap`, `warning`, `info`, `bell`, `crown`, `chevron`, `more`.

## 9. 문구

### 9.1 어조

| 원칙 | 예 |
|---|---|
| 해요체 존댓말 | "일정을 변경했어요" (○) / "변경되었습니다" (×) |
| 짧게, 한 문장에 한 가지 | "제안이 만료되었어요. 다시 요청해 주세요." |
| 할 수 있는 일을 알려 준다 | "인터넷 연결을 확인하고 다시 시도해 주세요." |
| 탓하지 않는다 | "어제 훈련을 놓쳤어요. 이번 주 일정을 다시 짤까요?" (○) / "훈련을 하지 않았습니다" (×) |
| 실패를 숨기지 않는다 | "변경하지 못했어요." (○) / 실패했는데 아무 표시 없음 (×) |
| 버튼은 동작을 말한다 | "적용하기", "기록 저장" (○) / "확인", "예" (×) |
| 의료 표현을 쓰지 않는다 | "통증이 계속되면 진료를 받아 보세요" (○) / "염좌로 보여요" (×) |
