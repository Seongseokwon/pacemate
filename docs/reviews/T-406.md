# T-406 교차 검토 (Codex)

대상: main `05d2a135`의 채팅 API, 메시지 처리기, 컨텍스트와 시스템 지침. 기준: PRD §11, API_SPEC §3.5·§6. 코드는 수정하지 않았다. 아래는 정적 검토와 기존 테스트의 내용이며, 실제 모델이나 기기에서 실행한 결과가 아니다.

## 수정 또는 확인이 필요한 사항

- **실패한 채팅이 기존 대기 제안을 대체할 수 있다.** T-405 검토의 동일 항목을 참고한다. 새 제안을 만든 후 응답이 실패하면 새 제안은 취소되지만 기존 제안은 `superseded`로 남는다. 사용자에게 새 제안이 전달되지 않은 상태에서 이전 제안을 쓸 수 없게 된다.
- **안전 응답과 도구 선택은 실제 공급자에서 아직 검증되지 않았다** (`AC-F04-01`, `02`, `04`, `07`, `08`). 시스템 지침과 평가 사례는 있으나 현재 공급자는 모든 호출에 실패한다. 심한 통증에 도구를 부르지 않는 규칙은 지침에 의존하므로 실제 모델 평가가 필요하다. T-407과 기기 확인에서 검증한다.

## 인수 기준별 결과

- `AC-F04-03`: 한도를 먼저 조회해 한도 도달 시 LLM 호출 없이 한도 카드를 저장한다. 기존 테스트가 호출 기록이 생기지 않는지 확인한다.
- `AC-F04-05`: 대화 조회는 사용자별 커서 페이지를 제공하고 실패 메시지도 포함한다. 기존 테스트는 재조회와 타인 대화 차단을 다룬다. 앱 재실행은 기기에서 확인해야 한다.
- `AC-F04-06`: 답 저장과 이용량 증가는 같은 트랜잭션이고 실패 시 메시지를 실패로 표시한다. 기존 테스트가 LLM 실패와 커밋 실패를 다룬다. 제안 대체 상태는 위 항목이 남는다.
- `AC-F04-07`: 코치별 지침과 공통 도구 정의를 분리한다. 기존 테스트는 코치 변경 시 지침과 도구 정의를 확인하지만 실제 말투 품질은 검증하지 못한다.
- `AC-F05-01`, `AC-F07-05`: 고정 LLM 대본을 쓰는 서버 통합 테스트에 S2와 S4의 제안·승인 흐름이 있다. S3의 실제 모델과 화면을 포함한 전체 흐름은 미확인이다.
- API_SPEC §3.5: 동일 ID 처리 중 202, 완료 후 저장 결과 재전송, 다른 메시지 처리 중 409, 실패 시 503을 구현하고 관련 테스트가 있다. 응답 유실과 실패 후 앱의 재전송은 T-408에서 확인해야 한다.

판정: 서버 구조와 고정 응답 테스트가 주요 계약을 다루지만 실제 공급자 평가와 전체 기기 흐름은 미완료다. 기존 제안 대체 문제는 수정 여부를 결정해야 한다.
